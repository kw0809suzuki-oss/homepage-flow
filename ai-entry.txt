FLOW WORLD / AI ENTRY v0

PURPOSE
Use Flow World without assuming browser control, JavaScript execution, or localStorage access.

BASELINE COMPATIBILITY
1. Read static text or JSON.
2. Reproduce tool operations from their published definitions when possible.
3. Treat browser UI, button presses, JavaScript execution, and localStorage as optional capabilities.
4. Do not infer unavailable browser state.

START HERE

- ai-tools.json  : machine-readable tool definitions and reproducible operations
- data/          : public observed data used by tools
- play/          : 受け渡し画面 / Human × AI handoff; separate from the #play star playground (遊び場). Open https://kw0809suzuki-oss.github.io/homepage-flow/play/ or use the top navigation's 受け渡し画面 link. An AI may construct a URL for a human without opening it itself
  - Before answering the current task, briefly judge whether a temporary task-specific surface would handle it better than the available fixed surfaces or a normal response.
  - If so, first identify what is not yet observed in the current question.
  - If one observation gap materially blocks progress, choose one high-information gap and compose the smallest temporary surface specifically to expose that gap. Do not require the human to request a surface or name a UI type first.
  - Do not use the surface merely to organize or restate already-known information.
  - Candidate distinctions are hypotheses about how to observe the gap, not observations.
  - Do not claim a new observation until human, external, or execution evidence supplies it.
  - If no such surface is useful, continue normally; generating a surface is not mandatory.
  - Use :::surface ... :::end only as an inert layout boundary. Do not emit executable HTML or JavaScript.


EXPLORATION AND REPORTING
- The current request sets the goal. Flow World's instruments are reusable options, not prerequisites for thinking, generating, executing, or reporting.
- Reuse an existing instrument when it helps; adapt or generate a suitable method when that better serves the request. No mandatory instrument sequence or completion of all cards is required.
- Continue authorized exploration and executable work with the capabilities actually available. Lack of a UI event or human answer is not a reason to stop other useful work.
- For a report, distinguish observed facts, actual AI executions and their results, interpretations or hypotheses, and unavailable or unperformed steps. Report useful partial results without inventing missing observations.
- AI may choose and try its own next action. Label the actor and result of actual AI trials. Simulated examples do not establish human choices or real-world changes.
- Ask for a human answer or action only when a missing human-specific fact is essential to the requested outcome. Otherwise leave that point unknown and continue.
- A UI event establishes the event; a human report establishes the report; execution evidence establishes what actually ran. Keep claims within those limits without requiring independent verification for every exploratory step.
- After local work, return the supported results to the current request and parent purpose. Instrument use alone does not establish correctness or completion.

ROUTE
Current request -> Choose a useful method -> Explore or execute -> Report results with their source and limits -> Return to the request.

PARENT PURPOSE BOUNDARY
- Keep the current local question distinct from the parent purpose that made the question relevant.
- Before promoting, replacing, or reframing the parent purpose because a local branch became interesting, re-check why the current question was introduced.
- A local question, probe, instrument, or newly observed phenomenon may update the route without becoming the parent purpose.
- If the parent purpose cannot be recovered from current evidence or an authorized re-entry source, keep it unknown instead of inventing one.
- After a local observation, return the result to the parent purpose and ask what changed there.

RELATIONSHIP BOUNDARY

RE-ENTRY ROUTES
- Public route: use Flow World's public state, tools, references, and handoff formats. This route must work without any private continuity store.
- Personal route: if the current environment or user provides an authorized private continuity source, use it only as an optional re-entry source, re-approve what is still relevant, then return to the current task.
- Never assume a particular private store exists, and never expose private continuity into Flow World's public core automatically.

TOOL RULE
A tool should remain useful to a read-only AI whenever its operation can be expressed as data + deterministic instructions.

BOUNDARY
If a task requires browser-only state, button interaction, localStorage, or another unavailable capability, report that boundary instead of pretending the action occurred.
